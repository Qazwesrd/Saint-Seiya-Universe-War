# 人物、美术、场景与装备制作规范

本项目目标为 Godot 4.4.1、Android ARM64、离线运行。程序化模型是可运行占位表现，不等于最终角色美术。正式模型必须由原创或已获授权的资源替换，并保留当前脚本接口。

## 1. 人物模型标准

每个可玩职业使用稳定 ID 命名：`<class_id>_body_<version>.glb`。推荐目录：

- `game/assets/characters/<class_id>/model/`：角色模型、骨骼和 LOD。
- `game/assets/characters/<class_id>/materials/`：护甲、皮肤、布料和发光材质。
- `game/assets/characters/<class_id>/animations/`：动画库。
- `game/assets/characters/<class_id>/portraits/`：职业头像和立绘。

必需动画：idle、walk、run、jump、fall、land、basic_attack_1/2/3、skill_cast、hit_light、hit_heavy、dodge、block、victory、defeat。天斗士和具备飞行能力的神明职业还需 flight_idle、flight_move、flight_rise、flight_dive、air_attack。

模型需提供 Root、Hips、Spine、Head、左右上臂/前臂/手掌、大腿/小腿/脚骨骼；护甲部件应支持独立挂点。角色至少准备近景LOD0、中景LOD1、远景LOD2。骨骼命名和动画事件必须附在资源说明中。

## 2. 职业视觉识别

32个职业的颜色、头饰、肩甲轮廓、背部装饰、发光强度由 `game/scripts/character_visual_catalog.gd` 管理。新增职业必须同步增加：
- SkillSystem职业定义和24项技能；
- CharacterVisualCatalog视觉配置；
- 职业选择头像/立绘；
- 初始装备、专属装备和小宇宙成长；
- 冒烟测试。

神明与天斗士应在轮廓、材质和特效层次上明显高于普通职业，但不得只靠整体缩放来区分。

## 3. 圣衣和装备资源

每套装备独立目录：`game/assets/armors/<equipment_id>/`，建议包含：
- `helmet.glb`、`chest.glb`、`arms.glb`、`waist.glb`、`legs.glb`；
- `materials/`、`textures/`、`icons/`；
- `manifest.json`：ID、类别、阵营、出处/原创标记、授权来源、部件、挂点、LOD、贴图尺寸。

装备家族包括青铜/白银/黄金圣衣、神圣衣、鳞衣、冥衣、神斗衣、天衣、刻衣和神明专属神衣。不同体系保持独立分类；不把神明神衣和圣斗士神圣衣混为一类。未核实的原作装备只保留档案，不伪造正式持有者或官方造型。

装备外观必须由装备栏和当前圣衣阶段驱动。装备强化、耐久、觉醒、套装效果应只影响对应部件或材质，不允许只换文字名称。

## 4. 场景资产与关卡

场景目录：`game/assets/environments/<chapter_id>/`。每个场景包含：
- 主地形、可行走区域、碰撞体；
- 远景/天空盒、主光源、环境光、雾效；
- 地标建筑、可交互NPC、传送点、战斗区域；
- 场景导航/出生点/任务触发点；
- 低中高画质配置。

主要篇章的视觉主题：
- 银河战争：竞技场、观众席、擂台边界和比赛灯光；
- 十二宫：十二座风格不同的宫殿、石阶和星座纹样；
- 北欧：冰雪山体、神斗士神殿、极光和寒雾；
- 海皇：海底神殿、七柱、潮汐光束和水下粒子；
- 冥界：冥河、墓园、审判空间、黑紫色灵魂光效；
- 天界：云海、神殿群、光门和高空平台；
- 原创终章：星域、时空环、虚空裂隙和终焉地标。

程序化地标可用于当前可运行版本，但正式关卡需替换为可探索的地形和建筑，不可把装饰环和柱子当成完整关卡。

## 5. 技能美术

技能特效按元素分组：火焰、冰霜、雷电、光、暗、海潮、风、时间、灵魂、星辰。每项技能需配置：
- icon_id、cast_effect、travel_effect、impact_effect、audio_id；
- 命中帧/伤害帧、范围提示、目标反馈；
- 颜色、粒子寿命、最大粒子数、屏幕震动等级；
- 移动端低/中/高画质降级参数。

同一技能的命中判定必须由战斗逻辑负责，粒子和动画只负责表现，不得用特效碰撞代替权威伤害计算。群体战斗应限制同时活动的粒子数和透明材质层数。

## 6. 移动端预算

以魅族21 Pro/Adreno 750为高档目标，同时保留低档降级：
- 优先共享材质和纹理图集；
- 避免大面积透明叠加和实时阴影；
- 远景关闭不必要的粒子和骨骼更新；
- 角色LOD按屏幕尺寸切换；
- 同屏敌人、召唤物、弹体和粒子数量必须有上限；
- 目标60 FPS，低档允许稳定30 FPS。

## 7. 资源验收

每次新增模型/贴图/动画必须检查文件可导入、资源路径、材质引用、骨骼映射、动画名称、碰撞体、LOD和移动端内存。CI通过只代表脚本/资源结构检查通过；最终外观还需在Godot场景和魅族21 Pro真机上验收。
