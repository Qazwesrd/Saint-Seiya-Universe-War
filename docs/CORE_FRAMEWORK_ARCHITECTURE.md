# 游戏底层框架与模块边界

## 目标

先把长期可扩展的底层骨架搭好，再集中制作完整内容。当前以 Android 横屏、Godot 4.4、ARM64、完全离线为边界；所有在线依赖都不属于本项目运行必需项。

## 模块分层

| 层级 | 模块 | 主要职责 |
|---|---|---|
| 应用入口 | `project.godot`、`scenes/main_menu.tscn`、`scenes/main.tscn` | 主菜单启动、游戏场景进入、渲染器、窗口方向、AutoLoad |
| 核心服务 | EventBus、SettingsManager、SaveManager、SceneFlowManager | 事件解耦、设置、通用文档存档、场景切换 |
| 内容服务 | ResourcePackManager、LocalizationManager、DialogueManager | 离线章节资源包、语言词条、剧情对话状态 |
| 表现服务 | AudioManager、HUD、Minimap | 音频路由、触控界面、地图标记 |
| 角色与战斗 | RPGState、SkillSystem、ArmorSystem、Enemy、Player | 职业、属性、技能、装备与实时战斗 |
| 玩法系统 | QuestManager、CampaignManager、CollectionSystem、SanctuarySystem | 任务、篇章、收藏、个人圣域 |
| 运营工具 | GMManager | 本地开发测试辅助，不作为玩家付费或联网系统 |

## 应用启动与界面导航

- `scenes/main_menu.tscn` 是应用入口；主菜单只负责开始/继续游戏、设置和退出，不直接持有战斗状态。
- `scenes/main.tscn` 保留为实际游戏场景，由 `SceneFlowManager` 统一进入。
- 主菜单完整设置页覆盖画质档位、帧率、渲染比例、阴影/特效开关、主/音乐/战斗/界面音量、镜头距离/灵敏度/反转、震动、自动拾取、左右手布局、按键尺寸、自动锁定、伤害数字、新手提示与中英文。设置服务负责类型校验、范围钳制、持久化和变更广播；帧率上限与音量立即应用，其他渲染/镜头/触控参数由对应表现模块订阅。
- 角色档案仍由 `RPGState` 管理。主菜单通过 `get_slot_summary` 读取摘要，不复制或维护第二份角色数据。
- `RPGState` 提供 `has_slot`、`get_slot_summary`、`create_new_slot`、`delete_slot` 和 `has_backup_slot`；三个槽位分别独立保存，删除前备份，恢复时校验版本。
- 主菜单提供三个本地槽位的新建、读取、备份、恢复和删除入口；删除前自动备份，且新建只允许空槽位，避免误覆盖。
- 设置页已提供上述全量配置项；尚需由最终角色相机、触控 HUD 和画质表现模块逐项接入并在 Android 真机验证。
- 首次建档向导、触控适配验收和完整设置页仍待后续完善。

## 全局服务调用约定

- 系统间广播状态变化优先使用 EventBus 信号。
- 单一数据归属：角色职业/背包/三槽角色存档由 RPGState 管理；任务进度由 QuestManager/CampaignManager 管理；设置由 SettingsManager 管理。
- SaveManager 只负责通用 JSON 文档和备份，不覆盖 RPGState 的角色存档格式。
- ResourcePackManager 只处理用户本地提供的资源目录：清单/版本/文件大小/SHA-256校验、依赖检查、剩余空间预检、暂存复制、原子切换/失败回滚、PCK/ZIP资源挂载和安全卸载；不提供网络下载。章节资源仍需单独制作和授权。
- DialogueManager 管理通用逐句对话状态；具体 NPC 对话内容仍由剧情数据提供。
- SceneFlowManager 是统一场景切换入口；当前原型仍以主场景内切换区域为主。
- 音频播放器和总线接口已建立；没有实际音轨/音效资源时保持静默。

## 章节资源包格式

每个安装包放在 `user://content_packs/<pack_id>/`，根目录包含 `pack.json`。示例：

```json
{
  "id": "galaxy_wars",
  "version": 1,
  "size_bytes": 123456,
  "files": [
    {"path": "maps/arena.pck", "sha256": "可选的64位SHA-256"}
  ]
}
```

文件路径必须是资源包目录内的相对路径，不允许绝对路径或 `..`。校验通过后才允许后续加载器接管资源。资源包删除前必须确认不是运行中的必需资源。当前提供本地目录安装 API、暂存校验与回滚、PCK/ZIP挂载、依赖与空间预检；尚未提供在线下载/差分更新，也没有随仓库交付的章节资源包本体。

## 目录和命名约定

- `game/scripts/`：GDScript 系统逻辑，文件名 snake_case。
- `game/scenes/`：可复用场景，按 world、characters、ui、effects 分类。
- `game/assets/`：只放自制或明确获授权资源，按 characters、armors、environments、animations、audio、vfx、ui 分类。
- `game/content/`：离线内容清单和数据定义，不放大体积原始素材。
- `docs/`：模块职责、资源制作规范、验收记录。
- `tools/`：无第三方依赖的仓库检查脚本。

## 质量边界

- 所有 AutoLoad 必须有且只有一个注册名，路径真实存在。
- 所有静态 `res://` 引用必须指向仓库内文件。
- 存档升级必须保留旧字段并提供默认值，不允许静默清空。
- 资源包需要版本号、大小和可选 SHA-256；缺失文件/校验失败必须明确报错。
- 不在仓库提交 APK、发布签名、私钥、用户存档或引擎缓存。
- 自动检查通过仅代表其覆盖的结构/解析/启动检查通过，不代表完整游戏内容或真机性能已验收。

## 本轮架构收尾补充

### 全局服务清单
- `EventBus`：跨模块信号契约；资源包状态统一使用字符串状态值，系统错误有独立事件。
- `SystemHealthManager`：离线错误记录、最近错误查询、受限大小日志与清理接口；日志仅保存在本机 `user://logs`。
- `ApplicationLifecycleManager`：Android进入后台时保存当前角色槽和设置，恢复时广播事件；保存失败进入本地诊断日志。
- `SettingsManager`：仅接受白名单配置键，统一做类型/范围校验，支持分区/全量重置；语言变更通知本地化服务。
- `ResourcePackManager`：资源包清单要求 `id`、`manifest_version`、`version`、`size_bytes` 和文件列表；每个文件必须提供精确大小及64位SHA-256。安装先复制到暂存目录并二次校验，再替换旧版；替换失败尝试回滚。依赖包不能缺失，基础包不能卸载，被依赖包不能卸载，已挂载包不能在运行中删除。

### 资源包清单规范
```json
{
  "id": "galaxy_wars",
  "manifest_version": 1,
  "version": 1,
  "size_bytes": 12,
  "dependencies": [],
  "files": [
    {"path": "chapter.pck", "size_bytes": 12, "sha256": "64位十六进制SHA-256"}
  ]
}
```
安装入口接收本机目录路径，不执行网络访问；校验通过后可以挂载清单中列出的 PCK/ZIP。资源包目录仍只是章节资源交付机制，不能替代实际地图、模型、动画、语音和剧情数据。

### 自动验收边界
GitHub Actions 当前执行静态路径/目录检查、Godot 4.4.1 导入解析、主场景启动及场景式框架冒烟测试。冒烟测试覆盖设置钳制与恢复、本地化切换、非法场景拒绝、资源包目录接口、系统日志、对话推进、通用文档存档、三槽角色存档备份/删除/恢复。CI 通过不等于 Android APK 已导出，也不等于真机触控、功耗、热量、内存或帧率已经验收。


## 核心玩法服务架构（阶段 1）

### 角色档案与多存档隔离
- 角色档案是每个存档槽的唯一持久化根；角色等级、背包、装备、技能、小宇宙、任务进度和剧情进度均保存在对应角色档案。
- `RPGState.slot_loaded(slot)` 仅在创建/载入/删除当前角色槽等生命周期操作时触发；任务和剧情服务订阅该事件重新载入，避免因经验或货币更新等普通状态变化而误重载。
- 旧版单档任务/剧情 JSON 在首次载入时迁移到当前角色档案；迁移成功后删除旧全局文件，避免新角色继续继承旧角色的剧情。
- 角色槽切换不共享任务目标、章节解锁、任务奖励领取记录。

### 战斗统计服务
- `CombatSessionManager` 管理单场遭遇生命周期、伤害输出/承受、治疗、技能施放、连招、击败普通敌人和 Boss、持续时间。
- 战斗事件通过本地信号发布，后续可供战斗结算面板、成就、战斗回放摘要和数值分析订阅。
- 统计仅记录本机当前战斗，不向外发送数据；离开场景时可调用 `finish_encounter()` 生成最终摘要。

### 离线战利品服务
- `LootManager` 统一读取普通敌人/Boss掉落表，按概率与角色等级修正生成物品。
- 所有掉落必须存在于 `RPGState.ITEM_DATA`，奖励通过 `RPGState.add_items()` 原子批量入账；校验失败或存档写入失败会回滚内存背包，避免只发放部分掉落。
- 当前掉落表只使用已定义的青铜装备和小宇宙药剂；后续章节专属装备、圣衣部件和材料应按资源包分表扩展，不在本服务硬编码未知设定。
- 不存在真实货币、联网抽卡或付费随机奖励。

### 运行时集成
- 银河竞技场遭遇启动时开启战斗统计；敌人受伤、玩家受伤、技能施放、连招和敌人击败均接入统计。
- 敌人击败时由统一掉落服务发放奖励，战斗提示展示实际掉落。
- Godot 场景式冒烟测试验证战斗统计汇总、非法物品拒绝、掉落接口以及多角色槽任务/剧情隔离。


### 装备词缀与套装共鸣（阶段 1.1）
- EquipmentAffixManager 是装备词缀与基础套装共鸣的唯一计算入口；词缀按装备部位写入角色档案，卸下该部位装备后其词缀不再计入属性。
- 当前词缀池包含攻击、防御、生命、速度和小宇宙上限；生成数量由装备品质等级限制在 1—3 条，且同一轮不重复。
- 当前套装共鸣只对已定义的青铜装备/青铜护腕族条目生效，2/3/4 件分别增加防御、生命、攻击与小宇宙上限。其他装备系列需在对应数据明确后再添加，不混淆天衣、鳞衣、冥衣等体系。
- RPGState.get_combat_stats() 汇总词缀和套装加成；词缀数据随角色槽保存，不使用网络服务或付费随机机制。
- 本阶段已添加场景式冒烟测试；实际通过状态以最新 Godot CI 为准。


### 技能成长与战斗结算（阶段 1.2）
- 技能树写入角色档案时采用事务式内存快照：只有 save_slot 成功才保留变更，失败则恢复原档案。分支选择、学习技能、技能栏装备、技能等级调整和重置均遵循这一规则。
- SkillSystem.get_skill_state(class_id) 汇总当前职业技能目录、学习状态、技能点、分支、装备栏位和学习条件；can_learn_ability 返回可读的阻止原因。
- EnemyDatabase 集中维护竞技场守卫、精英和 Boss 原型。敌人实例读取原型后应用有限的角色等级缩放，经验和星币奖励由原型定义。
- CombatSessionManager 在 Boss 战结束时计算 S/A/B/C 评价；HUD 结算面板只展示本地战斗统计和游戏内奖励，不涉及在线排名或付费货币。
- 本阶段未完成章节波次导演、复杂 Boss 行为树和正式角色动画；这些需要后续系统与资源阶段继续完成。


### 每日首领与 OL 式战斗节奏（新增）
- `DailyBossManager` 提供 7 日轮换的离线每日首领目录，按设备本地时间每日 05:00 刷新；角色存档槽分别记录当日首领、击败状态和奖励领取状态。
- 每日奖励领取后立即持久化领取标记，重复领取会被拒绝；设备时间回拨时不允许回到已记录的较新周期重新领取。
- 当前实现是本地设备时钟驱动的离线日常系统，无法获得服务器级可信时间；若玩家手动修改系统时间，离线游戏无法像联网 OL 一样进行权威校时。
- 战斗设计目标采用 OL 式即时动作节奏：主线按剧情顺序解锁、普通怪/精英/Boss 分层、Boss 预警与阶段招式、职业技能循环、小宇宙爆发和战后结算；保留单机操作与无服务器限制。
- 每日首领轮换数据与正式剧情 Boss 分离；日常挑战不能替代主线剧情中的指定 Boss，也不能提前解锁后续篇章。每日首领目前已具备轮换/状态/奖励服务，尚待接入专用挑战入口、独立场景与章节 Boss 实际战斗资源。


### 每日首领实战入口（本阶段新增）
- HUD 增加“每日首领”入口，显示今日轮换首领、每日 05:00 刷新倒计时、挑战状态与领奖状态。
- 玩家没有其他敌人交战时可发起独立每日首领遭遇；遭遇使用独立战斗会话，不推进主线剧情任务。
- 每日首领击败状态在战斗结束时写入当前角色存档；奖励需在每日面板手动领取，领取标记先持久化并阻止重复领取。
- 每日首领使用 Boss 战斗原型与独立难度增幅，普通战斗掉落保留；日常遭遇不会记入主线任务击杀进度。
- 倒计时基于设备本地时钟字段计算；离线环境无法抵御玩家主动修改系统时间。


### 剧情遭遇导演与多波次战斗（本阶段新增）
- `EncounterDirector` 统一管理离线遭遇 ID、波次顺序、当前波次、存活敌人数和遭遇结束信号。
- 银河战争篇的训练战斗已改为两波：第一波普通训练对手，第二波精英训练对手；完成后才进入训练 Boss 剧情任务。
- 训练 Boss 作为独立剧情遭遇由波次定义生成；每日首领使用独立战斗会话，不会推进剧情遭遇导演或主线击杀目标。
- 波次定义支持敌人原型、数量、出生位置和 Boss 标记，后续章节可用同一接口配置多波怪物与最终 Boss。
- 当前已接入的剧情实战仅覆盖银河竞技场训练任务；十二宫、海界、冥界、天界等章节仍需逐任务补齐剧情事件和遭遇配置。
