# 美术整改阶段：交付与验收门槛

本文件是本次整改的强制验收清单。**清单、目录、占位模型、自动生成的 blockout、CI 通过或 APK 成功导出，都不等于正式美术完成。** 未达到下列资产要求时，阶段状态必须保持未完成，不得发布为验收版。

## 一、最终交付规格

- 唯一目标平台：Android ARM64，横屏、离线单机。
- 最终交付采用**一个 APK + 国内网络自动下载离线数据**：玩家只下载并安装 APK，首次启动自动下载已发布的全部章节数据，不要求 VPN，不要求手动寻找、解压或复制数据包。
- APK 安装文件目标：**3–4 GiB**；首次启动自动下载的离线内容目标：**15–20 GiB 或更大**。实际容量只按真实可用资源计算，不得填充。
- 交付报告分别列出 APK 文件大小、各数据包大小、总下载量、安装后占用及临时空间。
- 资源必须是真实可用的游戏内容，不得用随机数据、空文件、重复贴图、填充文件或无用缓存凑容量。
- 目标设备：魅族 21 Pro；需要验证安装、启动、场景切换、战斗、内存、发热和帧率。
- 在完整资源未制作、导入和验证前，不得宣称达到 1–2 GiB 或美术完成。

## 二、必须实际交付的资产

### 1. 可玩职业角色
- 76 个职业均需独立可辨识的角色模型、面部/头发/身体造型、骨骼、材质、贴图和 LOD。
- 每个职业必须有可运行的待机、移动、跳跃、落地、三段普攻、技能施放、轻/重受击、闪避、防御、胜利和失败动画。
- 不能只用同一基础人形换颜色或改变数值充当 76 套最终角色美术。

### 2. 圣衣与装备
- 76 个职业都必须有黑暗圣衣；另有白金圣衣体系。
- 圣衣类别必须完整包含：青铜圣衣、白银圣衣、黄金圣衣、神圣衣、**神衣**、鳞衣、冥衣、天衣、黑暗圣衣、白金圣衣；各类别按独立装备体系逐套制作。神衣是独立类别，不得与神圣衣合并、改名或用同一套模型换色代替。神衣需有专属轮廓、部件结构、材质纹样、技能视觉表现与装备图标。
- 头盔、胸甲、左右肩甲、左右护臂、腰甲、左右腿甲需可独立装备/隐藏/破损；有材质、贴图、图标、挂点和 LOD。
- 黑暗/白金/神衣/神圣衣及各职业装备不得只通过换色或套用相同几何体冒充独立设计；每个类别都要在装备目录、模型资源、图标和游戏内装备界面中单独登记。

### 3. 七大篇章场景
- 银河战争、圣域十二宫、北欧、海皇、冥界、天界、原创终章各有可探索地形、建筑、天空/远景、光照、碰撞、导航、出生点、NPC/任务触发点和战斗区域。
- 十二宫各宫殿需体现差异；不得用少量柱子、圆环和空地冒充完整篇章地图。

### 4. 敌人、Boss 与战斗美术
- 普通敌人、精英、剧情角色和 Boss 需要实际模型、材质、骨骼/动作及必要的独立部件。
- 技能特效需对应技能实际效果，具有施放/飞行/命中表现、图标、音效标识和低/中/高档参数。
- UI 需有正式图标、头像、装备图标、技能图标、地图与菜单布局；所有控件在目标横屏尺寸可读、可触控。

## 职业规模补充要求

- 当前职业规划目标为 **76 个职业**：此前规划的 68 个职业，加上本轮保留的 8 个泰坦/宇宙系原创职业。
- 已取消东方神话职业分支：哪吒神将、二郎神、齐天战神、龙王、玄武神卫、朱雀神使、白虎战神、青龙神将，均不纳入职业目录、角色模型、技能、剧情或解锁内容。
- 保留泰坦巨神、普罗米修斯、大洋泰坦、光明泰坦、星界守护者、引力掌控者、次元行者、创世神使这 8 个原创职业方向。
- 每个职业至少 24 个专属技能，76 个职业合计至少 **1,824 个职业技能**；技能必须实际制作并在战斗中可用，不能只登记名称。
- 职业总数是规划目标，不代表角色模型、动作或技能已经完成。

## 小宇宙、战力与翅膀系统验收

- 小宇宙包含战斗能量积累/消耗/爆发、五感至第七感/第八感成长、小宇宙星盘节点、组件/套装培养；每项均须有可操作 UI、存档和战斗效果。
- 第七感、第八感须由等级、剧情和试炼逐步解锁；神职业另设神格成长，不得仅将凡人属性放大。
- 角色面板必须显示综合战力及可展开的分项来源，涵盖等级、职业、小宇宙、装备/圣衣、技能、翅膀、称号、伙伴/宠物/坐骑等；数值不得重复统计，战力变化须可解释。
- 新增战力翅膀系统：翅膀是独立外观/成长装备，需有独立模型、背部挂点、材质、图标、动作适配、阶位/星级/强化/进阶/觉醒、图鉴、属性和战力计算；支持隐藏与外观幻化。
- 翅膀主题可包含星辰、圣光、暗影、凤凰、海皇、冥界、天界、神域等原创系列；每个系列须独立设计，不得只换色或放大模型。
- 翅膀、小宇宙和觉醒特效必须提供移动端性能档位；魅族 21 Pro 横屏实测稳定性、温度、内存和帧率。
- 以上系统必须完全离线，成长材料通过游戏内任务、副本、Boss、探索或制作获得，不接入真实货币支付、在线充值或联网抽奖。
- 《圣斗士星矢OL》仅作为玩法体验参考；不得复制其客户端、代码、模型、贴图、动作、音乐或未获授权 UI。项目资源须自制或明确授权。
- 当前仓库已有部分小宇宙培养/能量数据和爆发入口，不代表完整小宇宙系统已完成；翅膀系统与战力分项面板等未通过实机验收前必须标记未完成。

## 三、资源真实性与技术验收

每个资产需有唯一 ID、来源/授权记录、文件路径、版本、格式、材质/贴图引用、LOD、移动端预算和状态。角色/装备/场景/敌人资源需实际导入 Godot 并在游戏场景中显示。

- 资产清单只有在 `source_license` 明确记录原创作者身份或可再分发许可证，并且 `quality_gate` 记录人工审核人、审核日期、`visual_review_required=false`、`approved_for_final_release=true` 时，才允许标记 `delivery_status=complete`。`pending_review`、`unknown`、`unverified` 等来源状态一律不能进入正式交付。

- 角色模型：GLB/glTF，具备真实骨骼蒙皮和有效动画轨道；不能只有骨架或静态网格。
- 圣衣：部件独立网格并绑定正确骨骼挂点；装备/卸下/损坏/修复在游戏中可见。
- 场景：有可行走空间和碰撞，不是只有装饰物。
- 特效：与真实战斗逻辑联动，并有移动端性能限制。
- 不能将 Blender 自动生成的 humanoid blockout、共享模板复制件或基础几何体标记为最终美术。

## 四、国内网络自动下载与容量验收

- 统计并记录最终可交付文件的真实字节数。
- 只计算必需的游戏资源；排除缓存、临时文件、重复文件和调试日志。
- 最终目标为 APK 3–4 GiB，首次启动通过国内网络自动下载 15–20 GiB 或更大的离线数据；必须报告真实值，尚未达到时如实标记未达标。
- 正式下载服务器须使用中国大陆可访问的 HTTPS CDN/对象存储，支持 HTTP Range 断点续传和 SHA-256 校验；不得依赖 VPN、境外网盘或 GitHub Release 作为正式下载源。
- 首次启动自动下载全部已发布章节；网络中断后可续传，下载校验完成后才允许进入完整游戏。
- 清除应用数据后重新安装，确认自动下载、校验、安装成功；断网后可进入所有已安装章节并完成战斗。
- 必须从干净安装开始验证资源包可读取，断网可运行，章节资源完整。
- 若资源尚未达到体积目标，必须如实报告未达标，不得填充文件凑数。

## 五、阶段完成定义

只有全部资产实际存在、来源合规、导入成功、游戏内显示正确、Android ARM64 构建成功、离线运行通过、1–2 GiB 交付规格通过，并完成目标设备测试记录后，才可将本阶段标记为完成并交给用户验收。

任何一项未完成，均应列为未完成项，不得以“源码已提交”“清单已生成”“CI 通过”代替。
